# NowX 设计文档（MVP）

> 定位：面向小团队（≤ 15 人）的轻量项目协作平台 —— 任务共享 + 材料共享 + 公告白板 + 交流论坛 + 项目助手。
> 目标：让「需求 → 任务 → 周期交付」可追溯，让团队内的问答沉淀为知识。

## 1. 核心工作流

1. 产品在飞书 / 腾讯文档写需求，另有正式的需求规格说明书等材料。
2. 在 NowX 中为每条需求建立「需求」条目：只存标题、外部文档链接、附件，不搬运原文。
3. 需求排入一个「计划交付周期」（两周 / 一个月）；开发负责人把需求拆解为一组「任务」，分配到个人，任务默认放入需求的交付周期，前置工作也可排在更早的周期。
4. 周期内大家推进任务；有疑问到「交流区」发帖，可关联任务 / 需求，所有人可见，形成存档。
5. 周期结束时查看完成率，按需求勾选顺延到下一期（未完成任务一并移出），进入下一个周期。

## 2. 已确认的决策

| 项 | 决策 |
|---|---|
| 部署 | 云服务器，Docker Compose（app + postgres + caddy） |
| 登录 | 账号密码，管理员创建账号，不开放注册 |
| 多项目 | 支持。项目是顶层容器，周期 / 需求 / 任务 / 交流区 / 材料 / 公告都归属于项目 |
| 语言 | 第一版仅中文 |
| 交流区形态 | 论坛 + 轻工单：全员可见可回复，可指定回答人，有状态，可采纳答案，可标记 FAQ |
| 项目助手 | 内置 Agent 机器人，回答与项目相关的简单问题（见第 6 节） |

## 3. 技术栈（为 Agent 维护优化）

- Next.js（App Router）+ TypeScript，单仓库全栈
- PostgreSQL + Prisma（`schema.prisma` 即完整数据模型）
- Tailwind CSS + shadcn/ui
- Zod 做前后端共享校验
- 自实现数据库会话认证（Argon2id 密码哈希；Cookie 存随机令牌，库中只存摘要）
- SSE 做实时刷新
- 文件存储：先本地磁盘，接口抽象，后续可切 OSS
- 测试：Vitest + Playwright（关键流程）
- 根目录 `AGENTS.md` 为开发规范，`README.md` 写明目录结构、约定与常用命令

## 4. 数据模型（概要）

```
User            账号：登录名、姓名、职能、平台角色(admin/member)、状态(正常/停用)、是否需改密、最近登录
Project         项目：名称、Key(如 CRM)、描述、归档状态
ProjectMember   项目成员：项目、用户（项目管理统一由平台管理员负责）
Cycle           周期：项目、名称、开始/结束日期、状态(计划中/进行中/已结束)
Requirement     需求：项目、编号、标题、外部文档链接[]、说明、负责人、状态、
                计划交付周期（空为待排期）、顺延来源周期
Task            任务：项目、编号、标题、描述(Markdown)、状态、优先级、负责人、
                截止日期、周期、来源需求、父任务
Comment         任务评论（支持 @）
Topic           交流帖：项目、标题、正文、作者、指定回答人、状态、
                关联任务/需求、是否 FAQ
Reply           回帖：是否被采纳；作者可为机器人
Material        材料：文件或外链、标签(多个)、关联需求
Tag             材料标签：项目、名称、颜色（项目内共享，成员可自行创建）
Announcement    公告：标题、内容、是否置顶
Notification    站内通知
Activity        操作日志
```

- 任务状态：待办 → 进行中 → 评审中 → 已完成（另有已取消）；进行中的任务遇到外部卡点时可标记为阻塞中，必须填写原因（作为评论保存并通知负责人），解除后回到进行中，并自动记录一条含阻塞时长的评论。阻塞计入未完成，结束周期时随未完成任务顺延
- 优先级：紧急 / 高 / 中 / 低
- 不记录工时。周期、需求、成员的进度统一按**顶层任务数**统计，子任务只在任务详情中体现
- 需求状态：待排期 / 设计中 / 开发中 / 已交付；外部文档链接自动识别飞书、腾讯文档等类型
- 需求可跨周期：交付周期是需求最后完成的那一期；任务排在交付周期之后时提示「晚于交付周期」
- 需求状态不随周期或任务自动变化：任务全部完成时只提示可标记为已交付；移动需求时默认带走未完成任务
- 交流帖状态：待回答 / 已解决 / 已关闭

## 5. 页面结构

- 登录
- 工作台：我的任务、待我回答、当前周期进度、置顶公告、最近动态
- 任务：看板 / 列表视图，按周期、负责人筛选；看板含「阻塞中」列，卡片显示已阻塞天数；任务详情抽屉（阻塞原因与解除、子任务、评论、相关讨论）
- 周期：周期列表、燃尽图、成员负载、本期需求、周期回顾（含需求交付 / 顺延统计）；结束周期时按需求顺延
- 需求：需求列表（按计划交付周期分组，外部文档链接、拆解进度）、需求详情（交付周期调整、拆解出的任务、材料、讨论）
- 交流区：帖子列表（全部 / 待我回答 / 待回答 / 已解决 / FAQ）、帖子详情
- 材料库：按标签浏览文件与外链，可新建 / 重命名 / 删除标签
- 公告：发布、置顶
- 项目设置（仅管理员）：项目信息、成员管理
- 项目管理（仅管理员，系统级）：新建项目、归档 / 取消归档、删除项目（需输入编号前缀确认，级联删除全部数据与文件，不可恢复）
- 账号管理（仅管理员，系统级）：创建账号（生成初始密码、选择加入的项目）、编辑、重置密码、停用 / 启用、删除（仅限没有任何协作记录的账号，其余只能停用）
- 权限：「管理」分组（项目设置、项目管理、账号管理）和「新建项目」只对管理员显示；成员直接访问这些地址会被拦截
- 项目助手：全局悬浮按钮 + 浮动对话框

## 6. 项目助手（Agent 机器人）

- 入口：可拖动的悬浮按钮（默认在右下角），点击在按钮旁弹出对话框；交流区可 @助手。
- 作用范围：当前登录用户 + 当前项目，**只读**。
- 实现：通过 `.env` 选择接口协议——Anthropic Messages API（默认 `claude-opus-5-5`，低思考强度，SDK Tool Runner）或 OpenAI Chat Completions（含兼容服务，自行驱动工具调用循环）；工具与协议无关，均为只读查询，范围固定为当前项目：
  - `list_tasks`（按负责人 / 状态 / 周期）、`get_cycle_progress`、`get_requirement`
  - `list_topics`、`read_topic`、`search_project`、`list_members`
- 未配置 `ASSISTANT_API_KEY` 时不显示助手入口，其余功能不受影响；每人每 10 分钟最多 30 次提问。
- 回答中引用的任务 / 帖子可点击跳转。
- 发帖时根据标题推荐相似 FAQ，减少重复提问。
